## 0.2 技术选型（已授权，直接采用）

- **HTML5 + CSS3 + 原生 JavaScript（ES Modules）**：整体页面、用户界面、游戏状态、输入与持久化。
- **Vite**：本地开发服务器与正式打包，采用 `npm install`、`npm run dev`、`npm run build`。
- **Three.js**：2.5D 场景渲染，**正交相机 + 实际三维平面与竖立展示牌**实现固定斜俯视的 2.5D 视觉，而非第一人称或自由旋转 3D。
- **Canvas 2D**：HOME 原图与 2D 角色、入口区域的渲染；与 Three.js 共用逻辑状态和键盘控制。
- **HTML/CSS DOM 叠加层**：学习卡、练习框、进度条、HUD、帮助、场景选择、睡眠与进食提示。DOM 文字要清晰、支持中文和 IPA。
- **localStorage**：单一存档的自动持久化；使用版本号、兼容迁移和损坏兜底。无需后端或用户账号。
- **音频**：优先复用`挑战/`项目中可合法使用的既有资源或逻辑，必要时 Web Audio API / `<audio>`。练习模式不提供发音。
- 如有必要，允许使用**仅用于素材预处理**的 Node.js 或 Python 脚本；交付的游戏运行时必须是浏览器网页技术，不能依赖启动 Python 游戏服务。

不要把项目写成一个几千行的单体 HTML。入口是 `index.html`，代码采用合理的模块化 JS/CSS 文件，打包后是可通过浏览器访问的 HTML 网页游戏。不得因“网页游戏”误以为所有代码必须内联一个文件。

技术参考：Three.js `OrthographicCamera`、`Sprite`、`Raycaster` 官方文档；Vite `public` 静态资源目录和构建文档。以项目安装的当前稳定 API 为准，不硬编码未经验证的老版本调用。

## 0.4 必须保护的产品规则

1. 用户提供的 HOME 原图与 `Home.txt` 层级是权威依据；Kitchen 下多个 Area 在同一可移动空间中，不能再做二级传送关卡。
2. 学习模式 **R**：接近词汇节点自动点亮，首次仅得 2 分；展示单词、音标、释义与英美音。
3. 练习模式 **F**：接近后只提供目标图片与英文输入；无需预先学习；不提供发音、单词拼写、释义和音标。
4. 练习按 V5 的**固定分支**执行：当前练习轮次第一次提交正确设为 5；答错设为 2；答错后在当前轮次重试正确设为 3；允许重复失败重试；答错时 R 可切整个场景到学习模式。
5. 词汇状态和积分以**最新有效学习/答题状态**为准；不要把所有分数持续累加，也不要擅自改为“历史最高分”。
6. 首页入口按 Space 打开模式选择，在其中按 R/F **选择并确认**进入相应模式。除练习答错后的特殊 R 操作，场景内不能任意切换模式。
7. 练习卡和学习卡由位置触发，没有独立关闭按钮；输入状态要避免按键冲突。
8. 游戏时间现实 1 秒 = 游戏 1 分钟；疲劳、饥饿为 0 时限制新学习交互；睡觉/进食不受限制；当前已开始的答题可完成。
9. 完成度达到 100% 弹一次完成界面；“继续探索”后不再自动重复弹出；“新开世界”清空当前唯一存档。
10. **明确假设：实际词汇不存在重复条目**。不要设计跨场景重复单词处理机制，也不要基于假想重复词增加问题或复杂度。

# 1. 游戏定位与体验原则

## 1.1 游戏名称与目标

产品名暂定：**HOME ATLAS · 灯语之屋**。副标题：**在家中漫游，让词汇逐一亮起**。UI 主要使用中文，场景名称与词汇显示原始英文；名称可在保持主题的条件下适度美化。

玩家控制一个微型人物，从真实 HOME 地图进入 Kitchen 等场景，在 2.5D 地面上沿思维导图结构漫游。区域（Area）是知识分组，图片展示牌是单词记忆锚点；学习模式提供完整记忆卡，练习模式要求仅凭图片回忆拼写。世界随着学习状态呈现不同的照明、颜色和进度。

**核心操作闭环**：HOME → 接近场景入口 → Space → 选择 R/F → 场景漫游 → 接近单词 → 学习或答题 → 状态/积分实时更新 → 返回 HOME → 探索其他场景。

不要用复杂任务系统替代这个核心闭环。

## 1.2 设计关键词

- **知识空间化**：思维导图节点关系在空间上清楚可见。
- **童话绘本 × 精致桌游**：温暖、有材质、安静、轻巧、具有探索吸引力。
- **2.5D 展示**：倾斜视角、俯视正交镜头，圆形地面节点、连接通路、竖直面向玩家的图像展示牌。
- **高可读性**：英文、国际音标、中文释义与输入框是视觉重心，场景只作为记忆背景。
- **低干扰反馈**：点亮光束、分数浮动、正确庆祝、错误轻提示，避免连续遮挡游戏。

## 1.3 不做的功能

不新增战斗、敌人、NPC 任务、物品背包、商城、排行榜、多人模式、抽卡、随机掉落、复杂养成、第三方登录或额外答题类型。后续若用户单独要求再扩展。

# 2. 页面总体架构与美术规范

## 2.1 页面架构

一页式应用，无整页刷新，至少包括以下状态：

1. 启动画面与素材加载（Loading）。
2. 首次进入：叙事与命名、皮肤选择（Onboarding）。
3. HOME 2D 游戏地图（Home）。
4. Home 场景入口模式选择（ModeSelect）。
5. 2.5D 场景·学习模式（StudyScene）。
6. 2.5D 场景·练习模式（PracticeScene）。
7. 帮助说明（HelpOverlay）。
8. 休息与进食的叙事交互效果（RecoveryOverlay）。
9. 世界完成结算（CompletionOverlay）。

不要把 UI 弹窗与底层游戏场景状态混为一谈；弹窗层通过明确状态控制输入优先级。

## 2.2 桌面端布局（主要支持 1366×768、1440×900、1920×1080）

```text

│ LOGO HOME ATLAS     [HOME > KITCHEN] [学习模式]   Day 02  14:20   ?  ⚙ │
├─────────────────────────────────────────────────────┬────────────────────────┤
│                                                     │  当前记忆卡 / 练习卡   │
│                  地图 / 2.5D 场景                    │ ┌────────────────────┐ │
│              角色、路径、Area、词汇牌                │ │    单词物品图片     │ │
│                                                     │ └────────────────────┘ │
│      左上或左下：区域导航 / 小地图                    │  单词 / 输入框         │
│                                                     │  音标 / 中文 / 发音    │
│                                                     │  状态提示与反馈        │
├─────────────────────────────────────────────────────┴────────────────────────┤

└──────────────────────────────────────────────────────────────────────────────┘
```

- 页面外层全屏沉浸式舞台，背景深色渐变与低对比纹理；中间游戏内容使用自然的面板边框和留白。
- 右侧卡片区常驻预留宽度，建议桌面宽 300–360px，空状态显示“靠近一件物品，开启记忆”。不要在游戏画面中央弹出巨型词卡遮挡地面。
- 顶部 HUD 高 64–76px：品牌、面包屑、模式、游戏时间、疲劳/饥饿简洁图标、帮助。
- 底部状态栏高约 56–88px：操作提示与总体进度，允许折叠过多次要信息。
- 小地图左上或左下，建议 180×180px，可在 140–220px 间响应式缩放。
- Canvas 填满剩余游戏区，并防止滚动条。右侧板与 Canvas 不得互相覆盖。
- 小于 1100px 宽时，记忆卡可变成底部可阅读面板；仍以键盘桌面操作为主要体验。可选手机虚拟摇杆，但不是本项目验收必需项。

整体采用**深蓝松绿夜色 + 奶油象牙纸面 + 金色灯光**，体现有温度的记忆地图。建议 CSS 变量：

```css
  --bg-raised: #1B3740;

  --ink-dark: #203540;

  --text-muted: #B5C5C4;
  --gold: #F1C874;

  --mint: #73CBB7;
  --coral: #ED8C7D;
  --blue: #78AEE5;

  --shadow-lg: 0 22px 65px rgba(1, 11, 17, .32);
  --radius-card: 20px;
  --radius-control: 12px;

```

**状态颜色不得只用色差区分**：未点亮=灰暗圆环/空心图标；已点亮=金色光圈+星点；直接正确=薄荷绿色双圈+√；错误=珊瑚红/橙脉冲+×；错误后正确=琥珀色光圈+修复符号。配色可微调，图标语义要稳定。

- 圆角卡片、透明磨砂边缘、低饱和描边、节制的微动效；禁止大面积炫光覆盖正文。
- 统一图标语言：线性图标用于 UI，轻立体彩绘用于地图。图标与背景保持足够对比度。
- 动画时长基准：按键反馈 100–180ms、卡片进出 180–260ms、点亮 450–750ms、烟花约 800–1400ms。尊重 `prefers-reduced-motion`。

## 2.4 角色设计

- 默认小人物是圆润的“探险学徒”：大头小身、深色短发、浅色衬衣、金黄背包，轮廓干净；至少提供 **3 种可选配色皮肤**，不必引入真实人物素材。
- 角色在 HOME 与 2.5D 场景中应保持相同的外观设定。可以用程序绘制角色精灵（Canvas texture）；若生成动画帧可加 4 方向步行、轻微上下摆动与地面软阴影。
- 人物始终明确可见；任何展示牌不得长期完全盖住角色。视线遮挡时将前景牌透明化或调整排序。
- 视觉尺寸相对道路宽度合理，人物碰撞点使用**脚底中心**，不是贴图矩形中心。

## 2.5 细节氛围

- 场景外缘为暗色虚空与细微星屑；地图主体像漂浮在夜色里的发光绘本舞台。
- Area 圆盘采用低高度的纸模/黏土式层叠地面，暖色侧边与柔和投影；连接道路像细窄丝带或木板桥。
- 场景节点有英文字牌和细光标识；词汇图像牌略带 3D 厚边、支架、轻阴影。整体要像精致小游戏，而不是矩形菜单堆积。
- 不同 Area 自动映射少量互补颜色与装饰纹样（如 Kitchen 水槽区水蓝、烹饪区暖橙），同一套设计系统内保持一致。
- 展示牌的图片优先使用真实源素材；边缘可生成纸张相框，不得让装饰喧宾夺主。

# 3. 地图与坐标系统

## 3.1 HOME：原图 2D 地图

- 用 `Home地图.jpg` 作为完整背景，按原始宽高比例渲染；鼠标或键盘操作不导致浏览器整页滚动。
- HOME 中渲染同一角色，可通过 WASD 连续移动。若原图比视口大，2D 相机跟随人物并限制视口越界。
- 根据原图和 `Home.txt`，给每个可进入场景定义**矩形、圆形或多边形入口热点**。入口热点与原图相应场景位置对应；Codex 应读取图片并确定热点，不可无依据地将入口位置随机摆放。
- 当角色进入热点的激活范围，显示轻量提示：`Space · 进入 Kitchen`。高亮入口地面环、轻微脉冲，重复按键不会双重加载。
- 按 Space 打开**模式选择浮层**，而不是立刻进入场景：`R · 学习模式` / `F · 练习模式`。按 R/F 确认后切换进入场景。支持点击对应按钮。Esc 关闭这个模式选择浮层。
- 回到 HOME 后优先放置在刚才入口附近的安全位置，避免立刻重复弹出。
- HOME 的行走区域应以原图可解释的区域为基础；若图片未提供可提取的精确边界，可以先允许人物在图像范围内移动，并通过热点进入场景。**不要臆造复杂的室内墙体碰撞**。

## 3.2 2.5D 场景坐标约定

- Three.js 世界：`x,z` 为地面水平坐标，`y` 为高度；人物脚点位于地图可行走表面 `y=0` 附近。
- 相机：`THREE.OrthographicCamera`，固定水平朝向（建议绕地图中心约 45°），对地面俯视角初值约 45°；轻微调整以保证展示牌和地图层级可读。**摄像机只平移跟随，不随人物方向旋转。**
- 角色按屏幕空间理解 WASD：W 在屏幕上方、S 下方、A 左、D 右；输入经过相机在水平面的基向量换算成世界 `x,z` 速度。支持斜向移动并归一化，防止斜向加速。
- 运动：按帧时间 `deltaTime` 更新位置，允许 60fps 平滑移动；遇到短暂掉帧进行 delta 限幅；停止即停、不出现漂移。
- UI 不参与相机旋转。场景内展示牌采用面向镜头的 `Sprite` 或锁定朝向的平面，保证英文字不随透视过度压缩。
- 图像节点的**地面触发区域**与其视觉牌分离，展示牌无物理碰撞（除场景外围限制外，内部装饰不妨碍自由移动）。

## 3.3 从思维导图自动生成场景

知识层级：

```text
HOME（2D）
  ├─ Kitchen（2.5D 单一连续场景）
  │    ├─ Cooking Area（同场景内的圆形区域）
  │    │    ├─ pan（词汇节点）
  │    │    └─ pot
  │    ├─ Sink Area
  │    │    └─ ...
  │    └─ ...
  ├─ Garden（2.5D 单一连续场景）
  └─ ...（按 Home.txt 实际内容生成）
```

- **每个 Scene 是单独可进入的 2.5D 地图，每个 Area 只是其中一个连续分区，不再用 Space 二次传送。**
- 场景中心为 Scene 核心圆盘（英文场景名 + 展示牌 + 返回 HOME 节点）；默认出生在中心相邻安全点。
- 根据 Area 数量 `N`，从画面逻辑最上方开始沿 360° 均匀分配 `N` 个方向。用 `angle_i = startAngle + 2π i/N` 初步定位区域；再做碰撞避让、半径与道路长度调整。
- 每个 Area 是圆形圆盘，中间有 `Area Name` 展示牌与图片；词汇节点沿一至多层同心圆环排布，尽量保证词汇展示牌距离均匀、没有重叠。
- Area 半径随词汇数量增长，不允许仅因节点过多就删除、隐藏或合并单词。节点密集时增加 Area 半径、环数、中心与其他 Area 的距离、相机缩放或文本 LOD（远看简化、近看清晰）。
- Scene 中心到各 Area 用**具有宽度的连续道路**连接，道路宽度必须允许小人物正常通过。道路两端与圆盘充分重叠，不能留视觉或碰撞缝隙。
- 可行走集合 = 中心圆盘 ∪ 全部 Area 圆盘 ∪ 所有连接道路多边形。外缘视觉围栏或灯带沿该集合边界生成；人物不得离开集合，内部装饰不产生障碍。
- Area 与单词牌可以有**轻微视觉厚度**，但可行走面在同一高度；无需真实上台阶、跳跃和动态寻路。这是保证 2.5D 视觉与操作稳定的选定默认设计。
- Scene 核心、Area 中心、单词节点使用不同视觉尺寸、形状和标签层级，一眼能看出知识关系。
- 连接线在地面可视化为道路与低亮度纹理，同时表达思维导图父子关系。

## 3.4 词汇节点交互区域

- 每个词汇节点由：词汇 ID、所属 Scene/Area、图像牌、地面锚点、触发半径、当前状态视觉构成。
- 人物进入有效半径后，该节点成为“当前激活词汇”，在右侧显示对应卡片；角色脚下可出现小型单词标签（仅学习模式），并显示光圈/状态效果。
- 同时靠近多个节点时，以距离最近者为当前词汇；使用 10%～20% 的迟滞区（hysteresis）防止走在边界处词卡闪动。
- 玩家离开全部节点有效范围时，非输入中的卡片返回空状态。再次进入可触发新一轮练习；无需额外关闭按钮。
- 场景中其他展示牌**不能阻挡角色移动**；只有外围行走边界阻挡。
- 必须支持位置验证：显示牌坐标、触发锚点、角色脚底坐标保持对应。提供可关闭的开发者调试叠层以查看触发范围和行走边界。

## 3.5 小地图

- 场景打开时小地图显示 Scene 全貌：中心、Area 圆盘、道路和人物光点，标注 Area 名称。
- 人物进入 Area 圆形范围后，小地图以动画平滑切换到 Area 局部图，展示该区域节点与角色位置；离开后恢复 Scene 总览。
- 靠近 Area 边缘时采用距离阈值迟滞，避免小地图来回切换。
- 小地图相对世界保持方向固定，人物标志实时同步；小地图支持切换总览/局部的状态提示，不强制添加复杂地图操作。

## 4.2 输入事件优先级

1. **真实文本输入框获得焦点时**：字母（含 `w,a,s,d,f,r,q,e`）只输入文字，不移动人物、不触发模式与发音。Enter 提交，Esc 退出文本编辑。
2. 启动叙事、帮助、模式选择、通关等遮罩浮层打开时：只响应对应 UI 的快捷键；背景游戏不响应移动、词卡交互。
3. 练习卡未编辑时：F 激活 / 重试，符合条件才允许 R 由练习切成场景学习模式。
4. 场景正常移动时：WASD 移动、Space 仅在返回 HOME 触发区生效，G 仅在床/进食范围生效。
5. 对按下/松开状态做正确处理，切换窗口或模态时清空残余按键；Space/R/F 禁止长按连续进入。

## 4.3 HOME → Scene 模式选择

接近 HOTSPOT → 显示 `按 Space 进入` → Space 弹出选择浮层：

```text
┌────────────────────────────────┐
│         进入 KITCHEN           │
│  选择一种探索方式              │
│                                │
│  [R] 学习模式  查看图文与发音  │
│  [F] 练习模式  看图拼写英文    │
│                                │
│      Esc · 暂不进入            │
└────────────────────────────────┘
```

- 浮层优雅、有半透明背景、轻缩放动画、两个清晰可点按钮。
- R/F 是**确认并进入**，不需要再按一次 Space；进入后 HUD 显示当前模式。
- 场景其他正常情况下不得直接用 R/F 改模式；要返回 HOME 重选。唯一特例为当前单词在练习中答错后，按 R 将**整个 Scene**切换到学习模式。

## 4.4 卡片与角色的非阻塞规则

- 学习卡**始终非阻塞**：靠近自动显示，离开自动隐藏/切换，人物仍可自由移动。
- 练习卡显示初始图片与输入区时也非阻塞；**当玩家按 F 或点击输入框后**进入文字输入状态，暂时暂停移动，并把焦点正确置于输入框。
- Enter 提交后退出文字输入焦点、恢复移动，右侧展示结果；错误时显示 `F · 再试一次` 与 `R · 切换整个场景到学习模式`；仍不添加关闭卡片的 X 按钮。
- Esc 仅用于退出输入焦点，不隐藏当前词卡；离开触发区域后卡片根据位置自动消失。
- 玩家保持在节点范围内时，答对状态不会每帧重复触发烟花与加分；若想重新进行该词测试，先离开节点触发区，再返回，开始**新的一轮**。
- 一个“练习轮次”以**进入同一词汇触发区**开始，以离开范围、退出场景、场景模式转换结束；本轮是否曾答错由运行时临时变量 `mistakeInRound` 控制。

# 5. 单词学习、练习与严格分支状态机

## 5.1 单词卡的数据内容

学习模式当前词卡包含：

1. 物品大图（优先真实图片，透明背景或自然画框），建议主体最大 240×200px。
2. 英文单词，大字号并可自动换行。
3. 美音 IPA 与 Q 图标 / 美国旗提示；英音 IPA 与 E 图标 / 英国旗提示，两者同一横排或响应式上下对齐。
4. 中文释义，字体 15–17px；必要时显示词性（仅当数据源提供可靠信息）。
5. 当前学习状态小图标 / 提示，避免遮盖主要词汇。
6. 右侧卡片底部可以有极简操作提示，不新增学习任务。

练习模式卡片**严格只显示图片、英文输入框、提交按钮、F/Enter 操作提示以及成功/失败的非答案反馈**。不得提前出现目标词、IPA、中文释义、发音按钮、音频提示或答案自动补全。Area 名与 Scene 名可在地图中继续显示。

## 5.2 词汇状态（唯一最终展示状态）

```text
UNSEEN           未点亮               0 分
LIT              已点亮               2 分
WRONG            错误回忆             2 分
CORRECT_FIRST    直接正确回忆         5 分
CORRECT_RETRY    错误后正确回忆       3 分
```

- 每个单词在任何时刻**只有一个当前状态**；当前状态决定地图视觉、词卡状态与当前分值。持久化保存当前状态即可，另存少量功能所需元数据（如进入触发区的标识、存档时间），不得额外生成并行的“历史最高积分”覆盖规则。
- 进入学习模式接近 `UNSEEN`：自动设置 `LIT`，0→2，出现金色光束和 `+2` 浮字，保存；此后仅靠近相同词汇不会反复加分，也不能把 `CORRECT_FIRST` 等练习成绩降回 `LIT`。
- 练习模式**不自动点亮**；靠近时只显示图片与输入。未经学习也可以直接练习，提交结果直接映射下表状态（积分中的“基础 2 分”是分值结构组成，不意味着玩家必须先经历学习模式）。
- **最新有效答题状态覆盖当前成绩**：若后续新一轮练习答错，原来的 `CORRECT_FIRST=5` 可以覆盖成 `WRONG=2`；若后续一轮首答正确，可以从 `WRONG=2` 变成 `CORRECT_FIRST=5`。这遵守 V5“只保留最新状态”。不要用历史最好成绩替代。
- 仍保留 `LIT` 状态与 `WRONG` 状态的不同视觉，虽然它们都值 2 分。

## 5.3 练习模式唯一合法答题流程

```text
进入词汇触发区
   ↓
仅显示图片 / 输入框 / 按 F 或点击输入框
   ↓
F 或点击输入框 → 开始输入
   ↓
Enter 或提交按钮 → 严格比较标准词汇拼写
   ├─ 本轮第一次提交正确 → CORRECT_FIRST → 5 分 → 烟花/正确反馈
   └─ 本轮提交错误       → WRONG         → 2 分 → 啊哦/错误反馈
                                     ↓
                             F → 重新输入
                                     ├─ 再错 → WRONG 2 分；继续可按 F
                                     └─ 答对 → CORRECT_RETRY 3 分；庆祝正确
                                     ↓
                             或 R → 整个 Scene 切换为学习模式
```

**重要：不要擅自增加“看答案”“选择题”“跳过”“提示次数扣分”“计时加分”“随机奖励”等额外路径。**

具体约定：

- 比较答案时仅做 `trim()` 与大小写不敏感处理；标点、空格和连字符按 `Home.txt` 的标准词条规范化（不随意接受同义词、近义词或拼写错误）。若是词组允许输入空格。
- 输入空字符串不可提交，显示轻提示而不判为拼写错误。
- 每次实际提交只更新一次状态，按钮与 Enter 防双重触发；音效、烟花和分值提示也只播一次。
- 提交错误：播放轻量“啊哦”音效，词汇节点变错误视觉，状态立即设 `WRONG` / 2 分；界面仅显示“再试一次”“按 F 重新输入”或“按 R 切换学习模式”。**不直接揭示标准答案。**
- 在**本轮已经有错误**的情况下，后续提交正确：设 `CORRECT_RETRY` / 3 分，播放庆祝，不升级成 5 分。
- 若玩家离开触发区并再次返回，开始新的轮次。下一轮首次提交正确就设置 `CORRECT_FIRST` / 5 分。这是为满足“只保留最新状态”与“100% 积分完成度可达”确定的默认规则。
- 答错之后，按 R 将**整个当前场景**改为学习模式，立即展示完整词卡，之后此 Scene 持续保持学习模式，直到返回 HOME；不把该操作解释为“只切换当前词卡”。
- 开始输入之后暂时阻止人物移动，答案提交或 Esc 退出输入后允许移动；没有独立关闭卡片按钮。

## 5.4 事件与状态测试表

| 初始状态 | 事件 | 新状态 | 本词新分值 | 视觉反馈 |
|---|---|---|---:|---|
| UNSEEN | 学习模式首次接近 | LIT | 2 | 金色点亮，+2 |
| LIT | 学习模式再次接近 | LIT | 2 | 保持亮起，不再加分 |
| CORRECT_FIRST | 学习模式再次接近 | CORRECT_FIRST | 5 | 保留绿色，不降级 |
| UNSEEN | 练习模式仅接近 | UNSEEN | 0 | 仅出现图片与输入提示 |
| UNSEEN / LIT / 任意已有状态 | 新轮次首次提交正确 | CORRECT_FIRST | 5 | 绿色、烟花，显示真实分值变动 |
| 任意状态 | 本轮提交错误 | WRONG | 2 | 错误色、啊哦，显示真实分值变动 |
| WRONG | 本轮已错误，再试又错误 | WRONG | 2 | 啊哦，无重复积分变化 |
| WRONG | 同轮错误后提交正确 | CORRECT_RETRY | 3 | 琥珀修复光圈、庆祝 |
| CORRECT_RETRY | 新轮次首次提交正确 | CORRECT_FIRST | 5 | 绿色、烟花，积分变化 +2 |
| CORRECT_FIRST | 新轮次提交错误 | WRONG | 2 | 红色、真实变化 -3 |

所有 `+2/+3/-3` 之类的浮动数值，必须展示 **新分值 − 旧分值**，不能每次答对就永久再加 5；零变化时可以只显示状态反馈，不显示 `+0`。

# 6. 积分、叠加进度条、完成状态

## 6.1 精确计算（权威规则）

- 每词分值 `score(word) ∈ {0,2,3,5}`；同一单词只保存最新有效状态对应的**一个当前分值**。
- Scene 当前积分 `sceneScore = Σ score(word)`。
- Scene 理论满分 `sceneMax = 5 × 当前场景实际词汇节点数`。
- Scene 积分完成度 `% = sceneMax > 0 ? round(100 × sceneScore / sceneMax) : 100`。若真实场景无词汇，视觉标注“暂无学习词汇”而非显示无意义的满分；全局完成判断要排除空场景并写明处理。
- HOME 全局积分为所有有词汇 Scene 的积分之和；全局理论满分为这些 Scene 的 `5 × 词汇数` 之和；全局完成度统一使用加权的 `Σ积分 / Σ理论满分`，不能用各场景百分比简单平均。
- **这里的“完成度”明确定义为积分完成度，不另外创造会与单条进度条冲突的第二个任务完成度。**达到 100% 意味着所有实际词汇当前都为 `CORRECT_FIRST = 5`，因此全世界可以通过重新开启新的轮次、首次答对恢复满分。
- 若显示整数百分比可能在未满分时因四舍五入显示 `100%`，通关判定必须按 `sceneScore === sceneMax`（全局 `worldScore === worldMax`），不能用四舍五入后的百分比。显示时未满分最高显示 `99%`，以避免假 100%。

## 6.2 单条三色叠加进度条

每个场景只用**一条三色叠加进度条**（未获得积分的部分是轨道底色），从左至右分别为：

1. **点亮基础段（金色）**：对分值为 2/3/5 的每个单词贡献 2 分；对未点亮为 0 分。
2. **直接正确附加段（薄荷绿）**：对状态 `CORRECT_FIRST` 的每词贡献 3 分。
3. **错误后正确附加段（琥珀橙）**：对状态 `CORRECT_RETRY` 的每词贡献 1 分。

因此 `barGold + barGreen + barOrange = sceneScore`，每段宽度占 `sceneMax` 比例；错误状态和仅点亮状态都贡献 2 分基础段，但错误词节点使用红色标记区分。顺序固定为**金 → 绿 → 橙**，右端显示该 Scene 积分完成度百分比与 `实际积分/满分`。

示例：Scene 有 10 个词，5 个仅点亮、3 个直接正确、2 个错误后正确：基础段 `10×2=20`，绿色 `3×3=9`，橙色 `2×1=2`，总积分 31/50 = 62%。

## 6.3 总进度与推荐场景

- HUD 或 HOME 进度面板展示所有 Scene 及对应一条三色进度条、全局总进度。场景排序沿 `Home.txt` 原始顺序。
- 使用一句柔和提示推荐**当前尚未满分**的某一场景，可选进度最低者；若全部满分，显示“整座家已被点亮”。
- Scene 里可以显示当前 Scene 的进度条；右侧词卡可简洁显示当前词汇状态，不增加另一条冲突的百分比。

## 6.4 通关与继续探索

- 当有词汇的整个世界第一次从非满分变为**严格满分**时，显示全屏恭喜结算（烟火、世界完成插画、积分总览、已亮起的房间）且只显示一次。
- 两个明确按钮：`继续探索该世界`、`新开世界`。
- `继续探索`：保留单一存档，设置 `completionShown=true`；即便再次答错导致积分从 100% 降低，**也不再自动弹出结算窗口**。界面显示当前积分百分比，可以从 100% 降至其他数值；不删除“曾完成”记录。
- `新开世界`：二次确认后清空该游戏的保存状态（勿清理浏览器其他应用数据），回到首次启动的命名、皮肤选择与开场叙事。此操作不可撤回，需要清晰提示。

# 7. 游戏时间、疲劳与饥饿

## 7.1 时间精度与计时

- 初始：`Day 1，08:00`；**现实 1 秒 = 游戏 1 分钟**，使用真实经过时间推进，不用每帧盲目加固定分钟数。
- 游戏内时间以整数分钟保存，可跨日，HUD 显示 `DAY 01  ·  08:00`，分钟正确补零。
- 打开首次开场、帮助、模式选择、游戏完成弹窗时暂停游戏计时；浏览器失去焦点时暂停，避免不在场时数值突然衰减。右侧普通词卡显示时计时正常推进；输入中的练习允许继续计时，但要保证正在进行的答案可以提交。
- 睡觉属于时间跳跃：立即推进到**下一个游戏日**的 08:00（不是简单把当前小时改成 08:00）；跳过的时长也计入“距上次进食时间”。睡眠黑屏、Zzz、淡入场景，建议总动画 1.2–2.2 秒。

## 7.2 疲劳值

- 睡醒时 `fatigue=100`；8:00 到 23:00 在 15 个游戏小时内线性降至 0，显示百分比与月亮或床图标。计算可采用自上次睡醒后的经过游戏分钟计；睡醒后满值、到对应日 23:00 降至 0。
- 23:00 以后直到玩家真正睡觉，疲劳保持 0 并设置 `needsSleep=true`；即使不睡觉一直等到第二天 8:00，也**不能自动恢复**，必须去床边按 G 睡觉。这与“必须找到 Bedroom 的床”一致。
- 可在任何时间进入床旁交互区按 G 睡觉；完成后醒在床附近安全位置（仍在 Bedroom），疲劳恢复 100。
- 疲劳为 0 时禁止**开启新的**词汇学习卡片或练习输入；人物移动、切换场景、返回 HOME、进食、睡觉、帮助均不受限。

## 7.3 饥饿值

- 初始饥饿值为 100，初始“上次进食”时间设为游戏 Day1 08:00。
- 从最近一次进食开始按游戏时间线性降低：`hunger = clamp(100 × (1 − elapsedMinutesSinceMeal / 1440), 0, 100)`；24 游戏小时未进食即为 0。
- 在 Kitchen / Dining Room 中的明确**进食标识节点**附近按 G，播放简单吃饭动画，恢复饥饿至 100 并记录当时游戏时间；无道具库存与消耗系统。
- 进食可随时执行，不因疲劳为 0 被禁止。睡眠期间饥饿继续根据跳过的游戏时长降低。
- 饥饿为 0 时禁止开启新的词汇学习/练习交互，其余移动、睡眠、进食可正常执行。

## 7.4 同时受限与“已打开的交互”

- 新交互开启条件：`fatigue > 0 && hunger > 0`。
- 词卡/输入框已经激活的情况下，即使游戏时间跨过限制阈值，仍允许**完成当前窗口的已有交互**；完成后新的词卡交互才被禁止。
- 进入受限状态后右侧显示不抢占操作的提示：`精力耗尽：去 Bedroom 找床，按 G 休息` 或 `饥饿：前往 Kitchen / Dining Room 的进食点，按 G 用餐`。如两者同时为 0，应并列提示两个恢复目标。
- 禁止学习时玩家仍能进入任意场景、经过任何 Area；节点依然显示，但不开放新学习卡或拼写输入。不要因为禁止学习而使返回 HOME / 睡觉 / 进食入口消失。
- 若存在“进入范围自动点亮”的竞争，在限制状态下不执行首次点亮。离开受限状态后**只要仍站在有效范围**，应允许触发一次，不能要求重启游戏。
- `Bedroom` 必须有床互动点；`Kitchen` 或 `Dining Room` 至少一个已可达的进食点。若实际词汇数据没有 Bedroom，仍可单独建立一个**标记为生活功能的 Bedroom/Rest 入口和床**，但不得将它虚报为 `Home.txt` 的词汇学习节点；同理可放置功能性进食点。这些辅助点不计积分。

# 8. 素材读取、数据标准化、音频

## 8.1 开发前素材扫描步骤

Codex 必须先：

1. 列出源文件夹下的文件名和格式，读取 `Home.txt` 的实际编码（UTF-8/GBK 等按真实情况检测）。
2. 解析缩进或树状结构，生成原始层级的机器可读 JSON，并对每个节点保留来源路径与顺序。
3. 读取 `Home地图.jpg` 原始尺寸并尽可能根据图像判断每个 Scene 的入口锚点；不能确定的热点放到单独可视化配置文件中，并在开发者模式提供拖拽微调工具及保存配置机制。
4. 扫描 `homeXmindPics`，查找 Area/词汇对应图片；自动裁剪与抠图仅用于确有必要的图像处理。严禁把 UI 截图上的一整张思维导图直接当作独立词汇物品图。
5. 读取 `挑战/` 既有代码以识别英音、美音调用方式，判断是否需要联网、可否离线运行、是否存在跨域限制或访问密钥。不可在客户端暴露秘密密钥。
6. 输出 `asset-report.json` + 开发日志：真实词汇数、已匹配图片数、缺少图片/音标/释义/音频条目。缺失时显示占位及显式告警，不能悄悄跳过。

## 8.2 词汇数据模型

建议统一的 `world.json` / 分场景 JSON（字段示意）：

```json
{
  "id": "kitchen",
  "name": "Kitchen",
  "kind": "scene",
  "sourceOrder": 0,
  "homeHotspot": { "x": 0.55, "y": 0.37, "radius": 0.06 },
  "areas": [
    {
      "id": "kitchen.cooking-area",
      "name": "Cooking Area",
      "image": "/assets/areas/cooking-area.png",
      "words": [
        {
          "id": "kitchen.cooking-area.pan",
          "word": "pan",
          "meaning": "平底锅",
          "ipaUS": "",
          "ipaUK": "",
          "image": "/assets/words/pan.png",
          "audioUS": null,
          "audioUK": null,
          "sourcePath": "Kitchen > Cooking Area > pan"
        }
      ]
    }
  ]
}
```

注：上面 `HomeHotspot` 数值与各图片路径、释义均为**格式演示**，不是已经读取到的事实。真实项目必须根据实际素材自动填入；不允许把演示词汇列表充作全部词库，也不能据演示坐标声称已完成 HOME 对齐。内部 ID 按唯一原始节点生成即可；已明确实际词汇不存在重复，不要另设去重逻辑。

## 8.3 图片处理

- 统一压缩到足以清晰显示的尺寸，保留原始资源；优先 WebP/PNG 透明背景，避免对大批原图做不可逆覆盖。
- 依据源数据匹配图片，不确定的条目保留源文件名和待确认标记，不强行把错图配给词汇。
- 缺图占位：精致纸面相框 + 类别中性简笔图标 + `图片待补充`，不能随机取一张不相关素材。
- 图片牌远处简化渲染，靠近清晰展现；预加载当前场景关键素材，其他场景按需加载，避免入口切换黑屏。
- 图像和说明文字在宽窄比例下自适应，必须防止图片被硬拉伸。

## 8.4 释义、音标和发音

- 最优先使用 `Home.txt`、原始素材中的可靠标注、既有 `挑战/`项目的数据和音频，不盲目自行编造单词释义或 IPA。
- 若只存在英文单词而缺少中文释义/音标，应接入**可信且允许使用**的词典数据来源，生成可核查的离线数据；无法联网或无法确认时，在数据报告中标记缺失，显示 `释义待补充` / `音标待补充`，不要写貌似真实的错误内容。
- 美音按钮显示 `🇺🇸 US · Q`、英音按钮显示 `🇬🇧 UK · E`，带喇叭图标，当前可播放时高亮；若仅有一方资源，另一方呈禁用并解释“该发音暂不可用”。
- 浏览器用户手势后再播放音频，捕获 Autoplay 错误；反复 Q/E 可中止或重启当前语音，不能无限叠加。
- 如果可使用浏览器 SpeechSynthesis 做降级，必须显著区分 `TTS 合成发音` 与真实词典美音/英音，不把没有英/美语音的合成结果伪装为双口音真人音频。
- 练习模式任何状态均不能播放目标词发音，不显示美英音按钮。

# 9. 叙事、引导、帮助与反馈

## 9.1 首次进入

启动加载界面使用烫金文字、柔和渐变、轻微星屑，呈现：

> 欢迎来到 HOME ATLAS。
> 这座家里，藏着等待被点亮的词汇。
> 沿着知识的道路走进各个房间，发现图像，唤醒记忆。

随后使用 2–3 个连续小面板说明：WASD 移动、Space 在 HOME 选择场景、R 学习、F 练习、靠近图片互动、`/` 帮助。支持跳过引导。

角色创建界面包括昵称输入（默认 `探索者`，建议不超过 16 字符）、三款可选皮肤的实时缩略预览、`开启旅程` 按钮。只首次创建存档时播放完整引导；后续从存档继续进入 HOME / 上次位置。

## 9.2 反馈细节

- 首次点亮：从节点底部升起细金光束，微小粒子聚拢，词汇牌描边由暗转亮，显示 `+2`。
- 练习直接正确：节点一圈薄荷绿光波，右侧轻烟花 / 彩纸粒子与 `答对了！`，用实际分差显示分值变化。
- 练习错误：一声较柔和的“啊哦”，输入框短暂抖动（可关闭动画），珊瑚色环，显示 `再试一次`；不出现刺眼报错或严厉措辞。
- 错误后正确：琥珀光环由断裂变完整，展示 `这次记住了！`，当前积分为 3。
- 交互限制：疲劳/饥饿图标低饱和闪烁一次，显示前往恢复节点的具体提示；不打断当前答题。
- 模式切换：场景顶部小条轻渐变，明确文字 `学习模式 / 练习模式`，避免不知当前模式。

## 9.3 帮助浮层

- `/` 或圆形 `?` 按钮呼出，展示按键对照、5 种单词状态及颜色/图标、分数说明、疲劳饥饿与进食睡眠操作、返回 HOME 的方式。
- 帮助内清楚解释：**当前分值反映最新一次有效练习结果，重复练习可能升降**；完成度为积分完成度。
- 按 `/`、Esc 或点击顶部关闭帮助（帮助窗口有关闭控件；词卡没有），恢复游戏。

# 10. 存档、加载与故障恢复

## 10.1 单一存档模型

存储键例如：`homeAtlas.save.v1`，保存一个带 `schemaVersion` 的 JSON：

```json
{
  "schemaVersion": 1,
  "player": { "name": "探索者", "skin": "amber" },
  "location": { "sceneId": "home", "x": 0, "z": 0, "mode": null },
  "worldMinute": 480,
  "lastMealMinute": 480,
  "lastSleepMinute": 480,
  "needsSleep": false,
  "wordStates": {},
  "completionShown": false,
  "onboardingSeen": true,
  "savedAt": ""
}
```

- 人物位置信息根据 HOME 坐标系统或 Scene 世界坐标系统存储，并带清晰标记，防止读取错位置。
- 词汇状态**只存当前结果**，总积分和进度条每次从词汇状态重新计算，避免缓存积分与状态不一致。
- 词卡首次点亮、每次练习提交、进食、睡眠、场景切换、角色创建/皮肤选择、通关选择应立即保存；人物位置每 3–5 秒节流保存，页面退出时尝试保存。
- 写入失败时显示简短错误提示，不能显示虚假的“已保存”；数据损坏时备份坏数据并以明确提示重新初始化，不要静默抹掉游戏进度。
- 新开世界清理且只清理此产品的存档与相关配置，不得调用 `localStorage.clear()` 清空整个域名。

## 10.2 浏览器适配

- Chrome / Edge 当前稳定版优先，Firefox 尽量兼容。
- 屏幕尺寸变化后更新 renderer 尺寸、相机投影矩阵、UI 布局；不让人物位置跳变。
- 在失焦、页面隐藏时停止捕获按键并暂停动画计时累积，避免恢复后一帧瞬移。
- 无 WebGL 时显示明确的兼容提示，而不是空白画面。

# 12. 分阶段实施计划与验收门槛

## 阶段 A：项目启动 + 原数据导入

**必须完成**：创建 Vite 项目、启动网页、加载原始 HOME 地图、读取 `Home.txt` 生成层级 JSON、整理图片、输出素材报告、页面初始化与资源错误提示。

**验收**：`npm install`、`npm run dev` 可运行；主页能看见用户 HOME 原图；实际 Scene/Area/词汇数量来自文件而非示例硬编码；无控制台致命错误。

## 阶段 B：角色和地图空间

**必须完成**：HOME 角色 WASD、入口热点、Space 模式选择、R/F 进入 2.5D；Scene 自动生成圆盘/有宽道路/展示牌；角色连续移动、边界阻挡、小地图、返回 HOME。

**验收**：角色可从 HOME 走到 Kitchen 并进入；Scene 内所有 Area 不需二次传送即可走到；所有词汇节点可达，角色不会掉出可行走面，摄像机不无限越界。

## 阶段 C：词卡与模式

**必须完成**：学习模式点亮、图文卡与 Q/E 发音；练习模式图片+输入、严格答题分支、R 答错后切整个 Scene 学习、状态颜色、动画、积分进度条、即时保存。

**验收**：所有状态测试用例通过；练习模式不泄露答案、不播放发音；历史分数不会无意累加；切换输入焦点时 WASD/F/R 行为正确。

## 阶段 D：叙事与世界系统

**必须完成**：欢迎叙事、命名/三皮肤、帮助、游戏时间、疲劳、进食、床与睡眠、受限提示、世界完成结算、单一存档与新开世界。

**验收**：达到 23:00 后需要睡觉；睡觉至次日 08:00；饥饿 24h 后受限；原已激活窗口可完成；恢复交互永远可达；满分结算只自动弹出一次。

## 阶段 E：视觉完成度和质量

**必须完成**：统一视觉规范、地图贴图与展示牌优化、过渡动画、光效、音效、进度条、高亮与卡片排版、多尺寸适配、键盘无障碍、性能检查。

**验收**：产品看起来是完成度高的小游戏，不是只有灰框、坐标轴和按钮的开发者原型；关键文字可读，词牌不重叠，移动顺滑，资源缺失有清晰状态。

**阶段原则**：每阶段都应有运行中的可验证成果；不要只完成 UI，忽略真实行走与答题行为；不要为了赶进度跳过世界系统或大量词汇节点。

# 14. 失败条件与禁止偷工减料

以下情形视为项目**未完成**：

1. 只做漂亮的 HOME 静态网页，人物无法在地图行走。
2. 点击按钮直接跳到词卡页面，没有 HOME 场景热点、Space 模式选择和场景内角色移动。
3. Scene 只是把原思维导图图片整体倾斜展示，没有重新绘制区域、连接道路、词汇牌和交互锚点。
4. Kitchen 中每个 Area 被错误做成单独传送页面。
5. 词汇列表只用演示 `pan/pot`，实际 `Home.txt` 节点未接入；漏掉实际单词或场景。
6. 练习模式提前展示答案、IPA、中文或播放目标词语音。
7. 分数用 `score += 5` 反复累加，导致超过每词理论满分或状态与进度不一致。
8. 输入词汇时 WASD/F/R/Q/E 键意外触发游戏行为。
9. 玩家被地图展示牌挡住或无法抵达区域，或被疲劳/饥饿系统永久锁死。
10. 刷新后人物、词汇积分、世界时间重置；或新开世界误删其他网页的 localStorage。
11. 虚称图片、IPA、音频已经接入，实则全部是占位、错配或静音。
12. 声称运行/测试成功，但并未真实执行命令、查看浏览器报错或验证交互。
